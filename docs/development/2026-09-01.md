## REQ-008 M1 说话人分析编排与处理引擎

### 实施基线

- 实施基线为 `main` 提交 `487ddaa`；仓库已有独立 8077 ECAPA 与 8078 pyannote 服务、冻结模型清单和 M1 权威算法参数，但没有统一单录音编排、结果 Schema 或评测执行器。
- Smart Badge 只作为固定快照的算法来源读取，没有修改相邻项目工作区，也没有迁入数据库、任务队列、身份声纹、ASR provider 或 Web 代码。

### 实际实现

- 新增不依赖 Torch、数据库或任务存储的 `voice_analysis_engine` 及独立 Python 3.11 环境，提供异步 `AnalysisEngine`、`analyze/evaluate` CLI、固定退出码和失败文件。
- 冻结 `StageExecutor`、`StageWork` 和五类阶段资源契约；M1 使用单任务内联执行，跨任务槽位、准入、持久状态与取消留给 M2。
- 音频使用 ffprobe 按内容探测，经 FFmpeg 单次规范化为 16 kHz 单声道 int16 WAV；规范化文件只在 `runtime/tmp/<run_id>` 存活，后续按时间区间随机读取。
- 8078 保持 `/segment` 兼容，新增临时根限制、逐候选状态和推理区间审计；pyannote 按原生 10 秒窗口及上下文重叠读取候选范围，不加载完整 PCM。
- 8077 协议保持不变；引擎统一去重黄金窗口和句段窗口，按最多 16 窗口、60 秒和 32 MiB 规划请求，单窗口最多读取前 30 秒。
- ASR speaker 只保存和回显；候选区只按时间和 500 ms 间隔合并。窗口评分、黄金窗口、密集/稀疏 NME、质量加权 KMeans、代表向量、medoid、70/90% 半径、严格归属和风险召回按冻结值实现，并固定随机种子及稳定排序。
- 新增 `voice_analysis_input_v1` 与 `voice_analysis_result_v1`，统一 `success/partial/unknown` 语义。结果不写 embedding；配置、输入扩展字段、metadata 和组件审计在公开前移除凭据与完整主机路径。
- `result.json` 是唯一权威输出，TXT、SRT、VTT 从落盘 JSON 派生并原子替换。系统性失败写 `failure.json`；显式截止时间在阶段前后和模型请求中检查。
- 新增 `config/analysis.yaml`；输入、组件、失败、导出与资源预算可覆盖，算法节禁止覆盖。结果记录脱敏配置、有效配置摘要和算法摘要。

## REQ-010 M1 监督质检与验收裁决

### 后发真值确认

- 用户确认后续提供的 12 份最终审核转写中，不同 speaker 标签在单份录音内准确对应不同自然人；标签文字虽然使用“咨询方”“顾客”“其他工作人员”等名称，评测时只把它们视为可置换的自然人编号，不解释业务角色语义。
- 本次确认使该 12 份最终审核转写可用于固定转写句段的自然人归属监督评测。来源时间仍为近似句段对齐，因此不能用它证明独立语音活动检测、精确说话人边界或完整端到端 DER。
- 自动评测只承担可重复计算；最终解释同时核对参考语义、指标计算对象、系统内部实际建簇数和错误构成，不以脚本状态机械替代监督结论。

### 监督评测结果

- 评测对象为 12 份独立录音、29,667,840 ms（8.241 小时）和 2,292 个句段；12/12 引擎运行均为 `success`，没有组件、鉴权、协议或推理系统性失败。
- 按录音宏平均，固定句段自然人错误率为 `0.492006`，JER 为 `0.735016`，已归属句段准确率为 `0.510550`，非 `unknown` 覆盖率为 `0.803653`，`unknown` 比例为 `0.196347`。
- 按有效发言帧微平均，固定句段自然人错误率为 `0.511264`，其中自然人混淆 `0.413638`、拒识漏分 `0.097626`、误检 `0`。主要错误是把已归属句段分给错误自然人，而不是拒识过多。
- 系统实际建立的全部簇用于人数复核后，人数完全正确率仍为 `0.333333`，人数 MAE 从自动报告按最终使用标签计算的 `0.666667` 修正为 `0.916667`。12 份中 5 份把 3 人合并为 2 人，2 份把 2 人拆为 3 人，`0518_184528` 把 2 人拆为 6 人，另 4 份人数正确。
- 1,455 个 `strong` 归属中 769 个正确，准确率 `0.528522`；267 个 `normal` 归属中 100 个正确，准确率 `0.374532`；116 个风险召回归属中 46 个正确，准确率 `0.396552`。当前等级反映规则命中，不具备真实正确概率校准意义。
- 256 个不足 1.5 秒的句段全部为 `unknown`，表明 M1 尚未利用前后长句锚点和局部连续性处理短句。
- 原始机器报告保留在 Git 忽略目录 `runtime/evaluation/recording2_authoritative_v1/evaluation-report.json`；本次监督复算没有修改结果文件、算法实现或冻结参数，也没有重新启动模型服务。

### 结论与已知风险

- 当前误差跨多份录音持续出现，且人数正确的录音仍可能存在高自然人混淆，因此监督结论将人数估计、黄金窗口聚类、句段归属和置信度校准识别为系统算法风险，不能归因于单份录音异常。
- 自动报告把最终至少使用一次的标签数作为预测人数，会掩盖未分配到句段的多余簇；该实现限制在本次验收中保留为已知问题，后续评测应同时报告实际建簇数和最终使用标签数。
- `m1_baseline_v1` 的数值门槛没有全部通过；12 份独立录音也未满足 20 份和完整场景覆盖要求。真实指标和 `insufficient_dataset` 事实保持不变。
- 用户最终裁决 M1 成果可以验收。验收范围是工程闭环、资源与安全边界、契约、真实模型运行和可评测能力；上述精度问题作为已知风险接受，不阻塞 M2，且不伪写为质量门槛已通过。

## REQ-011 M2 最小异步任务 API

### 实际实现

- 新增 8076 FastAPI 服务，提供鉴权上传、任务轮询、权威结果与 JSON/TXT/SRT/VTT 下载、尽力取消、主动删除、健康和 ready 接口。
- 新增可替换的进程内 `AnalysisBackend`；当前本地后端直接复用 M1 `AnalysisEngine`，默认单执行槽且不为新请求排队。准入预留与任务落盘分离，模型未 ready 或槽位被占用时返回 429 且不创建任务目录。
- 任务事实、输入和结果写入 Git 忽略的 `runtime/tasks/<task_id>`；客户端文件名不参与路径生成，状态文件使用原子替换。默认 24 小时删除业务资产，再保留最小 `expired` 状态 24 小时。
- 可选幂等键按规范化句段和音频摘要判定；同键同输入返回原任务，不同输入返回 409。创建过程在单进程内串行保护，避免并发重复创建。
- 取消请求与成功/失败终态使用同一任务锁裁决；M1 阶段边界协作取消，取消确认后的结果目录被丢弃。异步进度更新只允许作用于活动任务，shutdown 会等待分析后端结束。
- 启动时将遗留 `queued/running` 任务交给后端顺序从头重跑；带持久取消请求的遗留任务直接收敛为 `cancelled`。不实现断点续跑、自动重试、多进程或多节点。
- 更新 analysis 依赖锁、服务配置、环境模板、工作区验证、三服务联合启动/停止和组件测试入口；联合启动固定先等待 8077/8078 ready，再启动 8076。
