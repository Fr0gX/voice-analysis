# 2026-09-01 需求记录

## REQ-008 M1 说话人分析编排与处理引擎

### 用户原话

> PLEASE IMPLEMENT THIS PLAN:
>
> M1 新增独立于 HTTP、数据库和任务存储的 `voice_analysis_engine`，把现有 8078、8077 和 Smart Badge 固定快照中的权威算法串成确定性的单录音分析闭环。

### 目标行为

1. 新增独立的异步单录音分析引擎与 CLI，完成输入校验、单次音频规范化、候选区细化、窗口评分、ECAPA embedding、录音内人数估计与聚类、完整句段归属及 JSON/TXT/SRT/VTT 导出。
2. 引擎按音频 IO、8078 推理、8077 推理、CPU 聚类和导出 IO 声明阶段资源，只占用当前阶段资源；M1 提供单任务执行器和可由 M2 替换的执行接口，不实现跨任务持久队列。
3. 规范化 PCM 使用受控临时文件和随机区间读取，embedding 及聚类状态只在当前运行内存中存在，不建立数据库，不持久化 embedding，不建立跨录音身份。
4. ASR speaker 只保存和回显，不得参与候选区、人数估计、聚类、句段归属或 `unknown` 填充。
5. 原值提取固定 Smart Badge 快照中的窗口评分、黄金窗口聚类、NME、代表半径、句段归属与风险召回参数；算法配置锁定，产品输入、导出、失败和运行策略允许版本化覆盖。
6. 系统性组件失败使整次分析失败；局部窗口或句段推理失败返回部分结果；质量门或拒识产生的 `unknown` 是合法成功结果，不伪装为组件成功或人员身份。
7. `result.json` 是权威结果，其他文本格式只从该 JSON 派生；结果和日志不得包含 API key、完整主机路径或 embedding。
8. 实现按 `config/evaluation.yaml` 执行的 M1 评测入口，数据不足时返回 `insufficient_dataset`，满足数据规模时逐项输出实际值、门槛和结论。

### 默认边界

- 沿用 REQ-006 的音频格式、1 GiB、400 ms 至 4 h、句段规范化、导出和失败策略。
- 沿用 REQ-005 的权威算法参数以及 8077 的 16 窗口、60 秒、32 MiB 批次限制。
- 内存目标为可用额度的 80%，90% 为硬限制；完整音频不长期驻留内存。
- CLI 默认无总截止时间；显式截止时间贯穿全部阶段。

### 验收

- CLI 能对合法音频和 ASR JSON 生成权威 JSON 及 TXT/SRT/VTT，并保留全部原始句段。
- 固定资产算法 parity、确定性、输入边界、局部/系统失败、长音频有界内存和真实模型端到端测试通过。
- 8077、8078 现有组件契约保持兼容，新增字段和受控临时目录支持不放宽主机路径边界。
- M1 不引入数据库、公开异步任务 API、Web 页面、任务恢复或跨录音身份。

## REQ-009 “录音2”弱标注评测集构建与校验

### 用户原话

> 那你就复制成20份；相关校验、标注由你完成

### 目标行为

1. 从相邻 Smart Badge 项目的 `refer/录音2` 读取 12 份 MP3 及配对角色标注，不修改来源资产；在本项目 Git 忽略的运行目录内建立 20 份可重复生成的 M1 评测样本。
2. 不以同一文件的字节级复制冒充独立录音。通过对长录音按转写边界切分，形成 20 个内部不重叠、带源文件和时间偏移溯源信息的样本；报告同时记录 12 个独立源录音和 20 个派生样本。
3. 将 Markdown 转写转为 `voice_analysis_input_v1` 和评测参考标注；修复秒级标注中的零时长区间，统一重复 `_overlap` 后缀但保留原始标签、语义角色、修复原因和弱标注质量信息。
4. 对源音频、配对文档、声明段数、解析段数、音频时长、样本边界、输入 Schema、参考标签、场景构成、文件摘要和派生音频进行校验，生成机器可读验证报告。
5. 使用真实 8077/8078 执行派生清单并输出实际评测报告；任何失败、`unknown`、不满足门槛或标注限制如实报告。

### 真值与验收边界

- 来源文档明确声明文本来自内部 ASR、角色由语义归类且未进行真实身份核验，因此本次参考只能标记为 `weak_automatic_reviewed`，不能改写为人工身份真值或公开数据集。
- 20 个样本来自 12 个独立源录音，满足技术执行器的样本数量输入，但不能把派生数量解释为 20 个独立采集会话；正式业务门槛结论必须显式保留此限制。
- 构建器可重复运行，不把音频、转写正文、模型结果或评测报告提交到 Git；仓库只保存构建与验证逻辑、契约和真实开发记录。
