## REQ-006 M1 输入边界与可配置产品策略

### 用户原话

> 1. 我想至少兼容主流音频格式，大小、时长区间你根据主流情况来定；
> 2. 其他的可配置；

### 音频默认边界

1. 首版支持以下常见录音容器或编码：WAV/PCM、MP3、FLAC、M4A/AAC、OGG/Vorbis、Opus、WebM/Opus、AMR-NB/AMR-WB 和 3GP。实际格式必须依据文件内容探测，不能只信任扩展名；容器或编码无法解码时显式拒绝。
2. 默认单文件必须非空且不超过 `1 GiB`（`1,073,741,824` bytes）。
3. 默认可分析时长为 `400 ms` 至 `4 h`（`14,400,000 ms`）。400 ms 与现有 ECAPA 最短窗口权威值一致；超过范围时在完整模型处理前拒绝。
4. 解码统一输出 16 kHz、单声道、signed int16 PCM。实现应先探测文件、音轨、时长和资源边界，再执行完整解码，避免以完整解码作为超限判断手段。
5. 支持格式、文件大小和时长限制进入版本化配置；以上数值是首版默认值，覆盖后的解析结果必须写入结果元数据。

### 其他产品策略

M1 新增版本化分析配置，建议入口为 `config/analysis.yaml`。CLI 或后续调用方只能覆盖公开配置项，最终生效配置及其版本必须进入审计元数据。默认策略如下：

1. ASR 句段要求 `id`、`start_ms`、`end_ms` 和 `text`；`confidence` 与原始 `speaker` 可选。默认按时间稳定排序并保留原始输入序号，允许重叠；重复 ID、无效区间和音频越界拒绝；空文本保留并告警；缺失置信度保存为 `null`。
2. 原始 ASR speaker 默认允许输入、保留并回显，但只作为审计字段，不能参与说话人数估计、聚类、句段归属或 `unknown` 填充。该字段的接收和回显可以关闭，算法禁用边界不可配置。
3. JSON 是完整权威结果，保留原始句段字段，并增加本地 speaker、`unknown`、置信度、依据、风险、组件状态和版本元数据。TXT、SRT、VTT 默认使用 `[local_spk_n]` 或 `[unknown]` 前缀保留原文；是否附加置信度、依据和风险可以配置。
4. 8077、8078 未就绪、鉴权/协议错误、超时或系统性推理失败默认使整份分析失败；单个候选窗口或句段向量失败默认返回部分结果，把受影响句段保留为 `unknown` 并附带明确告警。严格失败或部分结果策略可以配置，但不得丢失原始句段。
5. 配置覆盖只改变输入规范化、展示和失败策略，不改变 REQ-005 确认的算法资产权威阈值；算法参数如需改值仍必须建立新的明确需求。

### 开发与验收边界

- 上述默认值已经解除 REQ-005 中输入、输出、失败和 ASR speaker 口径对 M1 开发的阻塞；具体 Schema 字段组织和配置结构由实现按这些语义设计并版本化。
- 合法脱敏评测集和业务指标目标仍需在 M1 业务验收前由人提供，但不阻塞模块和契约开发。
- 解码格式、大小、时长、句段规范化、导出和失败策略必须有默认值、配置覆盖和边界测试。

## REQ-007 M1 基础评测门槛配置化

### 用户原话

> 1. 你自己给一个基础值；
> 2. 做成配置；

### 基础值

M1 首版使用以下冷启动业务验收门槛，全部指标同时通过才算基础评测通过：

1. DER 不高于 `0.30`，JER 不高于 `0.40`；使用 `100 ms` 评分帧、`250 ms` collar，并计入重叠语音。
2. 说话人数完全正确的录音比例不低于 `0.80`，说话人数平均绝对误差不高于 `0.30`。
3. 已分配为非 `unknown` 的句段归属准确率不低于 `0.85`。
4. 非 `unknown` 覆盖率不低于 `0.80`，`unknown` 比例不高于 `0.20`；拒识句段不能从分母中删除。
5. 基础评测集至少包含 `20` 份录音、合计不少于 `60` 分钟，并至少覆盖单人、双人、多人、重叠和噪声/远场五类场景各 `3` 份。单份录音可以同时计入多个场景。

比例和误差指标默认按录音宏平均，speaker 标签在评分前允许做最优置换映射。PriMock57、AISHELL-4 和 AliMeeting 等原仓库已有适配器的公开合法数据作为默认数据来源；MagicData-RAMC 仅在用途符合其非商业许可时使用。实际业务录音可以补充，但不再是启动 M1 技术验收的必要前提。

### 配置要求

1. 在 `config/evaluation.yaml` 中保存配置 schema、Profile 版本、数据集最低规模、评分策略和全部门槛，不把数值散落在评测代码或测试中。
2. 评测入口允许通过明确的配置文件替换默认 Profile；运行报告必须记录配置版本、配置文件摘要、实际数据集构成和每项通过/失败结果。
3. 配置项属于验收标准，不覆盖 REQ-005 的算法资产阈值。修改基础门槛不需要修改算法实现，但配置变更仍需进入版本管理并留下需求和评测记录。
4. 缺少最低数据量或任一必需场景时，结果只能标记为 `insufficient_dataset`，不能按已通过处理。

### 验收

- `config/evaluation.yaml` 能被标准 YAML 解析器读取，数值和本需求一致。
- `PROJECT_STATUS.md` 不再把评测指标目标列为待人工提供项；公开数据评测可以独立启动。
- M1 实现完成后，评测报告必须逐项输出实际值、门槛和结论。
