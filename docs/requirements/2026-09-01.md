## REQ-008 M1 说话人分析编排与处理引擎

### 用户原话

> PLEASE IMPLEMENT THIS PLAN:
>
> M1 新增独立于 HTTP、数据库和任务存储的 `voice_analysis_engine`，把现有 8078、8077 和 Smart Badge 固定快照中的权威算法串成确定性的单录音分析闭环。

### 目标行为

1. 新增独立的异步单录音分析引擎与 CLI，完成输入校验、单次音频规范化、候选区细化、窗口评分、ECAPA embedding、录音内人数估计与聚类、完整句段归属及 JSON/TXT/SRT/VTT 导出。
2. 引擎按音频 IO、8078 推理、8077 推理、CPU 聚类和导出 IO 声明阶段资源，只占用当前阶段资源；M1 提供单任务执行器和可由 M2 替换的执行接口，不实现跨任务持久队列。
3. 规范化 PCM 使用受控临时文件和随机区间读取，embedding 及聚类状态只在当前运行内存中存在，不建立数据库，不持久化 embedding，不建立跨录音身份。
4. ASR speaker 只保存和回显，不得参与候选区、人数估计、聚类、句段归属或 `unknown` 填充。
5. 原值提取固定 Smart Badge 快照中的窗口评分、黄金窗口聚类、NME、代表半径、句段归属与风险召回参数；算法配置锁定，产品输入、导出、失败和运行策略允许版本化覆盖。
6. 系统性组件失败使整次分析失败；局部窗口或句段推理失败返回部分结果；质量门或拒识产生的 `unknown` 是合法成功结果，不伪装为组件成功或人员身份。
7. `result.json` 是权威结果，其他文本格式只从该 JSON 派生；结果和日志不得包含 API key、完整主机路径或 embedding。
8. 实现按 `config/evaluation.yaml` 执行的 M1 评测入口，数据不足时返回 `insufficient_dataset`，满足数据规模时逐项输出实际值、门槛和结论。

### 默认边界

- 沿用 REQ-006 的音频格式、1 GiB、400 ms 至 4 h、句段规范化、导出和失败策略。
- 沿用 REQ-005 的权威算法参数以及 8077 的 16 窗口、60 秒、32 MiB 批次限制。
- 内存目标为可用额度的 80%，90% 为硬限制；完整音频不长期驻留内存。
- CLI 默认无总截止时间；显式截止时间贯穿全部阶段。

### 验收

- CLI 能对合法音频和 ASR JSON 生成权威 JSON 及 TXT/SRT/VTT，并保留全部原始句段。
- 固定资产算法 parity、确定性、输入边界、局部/系统失败、长音频有界内存和真实模型端到端测试通过。
- 8077、8078 现有组件契约保持兼容，新增字段和受控临时目录支持不放宽主机路径边界。
- M1 不引入数据库、公开异步任务 API、Web 页面、任务恢复或跨录音身份。

### 真值解释

1. 用户后发确认的 12 份最终审核转写中，每个不同 speaker 标签在单份录音内对应一个确定自然人；“咨询方”“顾客”“其他工作人员”等文字只作为标签名称，不按业务角色语义参与人数、聚类或归属判断。
2. 该后发确认覆盖此前将这批最终审核转写理解为仅能评价角色一致性的判断，但不追溯改写 REQ-009 形成时对旧自动弱标注派生集的真实记录。
3. 最终审核转写的自然人分配作为本次监督评测参照；其时间轴仍是近似句段对齐，因此当前结果可评价固定转写句段上的自然人归属，不能扩张为独立语音活动检测和精确说话人边界的完整 DER 结论。

### 监督质检口径

1. 自动评测器负责可重复计算和汇总，不单独裁决参考资格、指标含义、错误归属或最终验收。
2. 监督质检必须先确认真值代表的是自然人、区分固定句段归属与端到端 diarization，并核对系统实际建立的全部簇数量，不以最终至少使用一次的标签数量替代系统人数。
3. 自动报告中的非 `unknown` 覆盖率和 `unknown` 比例互为补数，只能作为同一拒识行为的两个视图，不解释为两项独立质量证据。
4. 报告保留真实未达标项，不因人工验收而改写实际值或伪造门槛通过。

### 验收裁决

1. M1 的处理闭环、组件兼容、资源边界、确定性、结果契约、失败表达、真实模型运行和评测能力按本次成果验收通过。
2. 12 份自然人参照录音上的人数估计、聚类混淆、句段归属置信度和短句拒识问题作为已知算法风险接受，不阻塞进入 M2。
3. 本次用户验收是里程碑成果验收，不等同于宣称 `m1_baseline_v1` 的全部数值门槛通过，也不改变 12 份独立录音和场景覆盖不足的事实。
4. 后续优化以实际建立簇数、自然人混淆、置信度校准和短句上下文归属为重点，并以新的明确需求决定是否调整冻结算法参数。

## REQ-011 M2 最小异步任务 API

### 用户原话

> PLEASE IMPLEMENT THIS PLAN:
>
> 新增单机 FastAPI 服务，职责限定为：安全受理输入、保存任务事实、向分析后端交付、查询状态与结果、转发取消、删除及过期清理。

### 目标行为

1. 新增统一任务 API，沿用 `X-Voice-Analysis-Key`，支持创建、轮询、结果与导出下载、尽力取消、主动删除和 24 小时自动过期。
2. M2 不建立执行队列或决定任务分配；它通过可替换的进程内后端接口原子准入并交付任务。当前后端直接复用 M1 `AnalysisEngine`，默认单执行槽且不排队；容量不足直接返回 HTTP 429，且不创建任务。
3. 任务事实、输入和结果保存在受控本地任务目录，状态使用原子 JSON 更新；不持久化 embedding，不使用客户端文件名构造主机路径。
4. M1 的 `success` 和 `partial` 都映射为任务 `succeeded`；M1 结果仍保留其完整状态、警告和审计。系统错误、截止时间和取消分别表达，不把迟到结果发布为成功。
5. `Idempotency-Key` 可选；同键同输入返回原任务，同键不同输入返回冲突。显式 `deadline_sec` 必须大于零，默认不设置总截止时间。
6. 启动时把遗留 `queued/running` 任务重新交付并从头执行；不实现断点续跑、多进程抢占、多节点、数据库、自动重试、SSE、WebSocket 或 Web 页面。

### 数据与清理

- 输入和结果默认保留 24 小时；过期后删除业务资产，只保留最小脱敏 `expired` 状态 24 小时，随后删除整个任务目录。
- `queued` 任务可在后端开始前取消；`running` 任务由后端在 M1 阶段边界协作取消，不承诺强制中断正在执行的解码、模型请求或 CPU 计算。
- 日志不得记录音频正文、完整转写、embedding、API key 或完整主机路径。

### 验收

- 可重复验证成功、部分结果、输入失败、系统失败、截止、取消、删除、过期、幂等冲突、容量拒绝和重启重新交付。
- 未授权请求不能读取、取消或删除任务；路径逃逸、恶意文件名和越界删除被拒绝。
- 真实 8077/8078 能完成一次从上传到 JSON/TXT/SRT/VTT 下载的闭环。

### 用户原话

### 目标行为

1. 新增仅限本机访问的 React + TypeScript Web，提供“音频加现成 `voice_analysis_input_v1`”和“音频加单次腾讯/阿里 ASR 凭据”两个入口，最终统一进入 M1 分析、复核和四种导出。
2. 新增腾讯、阿里云 ASR provider 边界，把供应商结果规范化为现有输入契约；供应商 speaker 只保存为审计来源，不参与人数估计、聚类、归属或 `unknown` 填充。
3. ASR 凭据只在当前浏览器内存和服务端活动任务内存中存在，不持久化、不回显、不摘要、不进入幂等摘要、任务事实、结果或日志；终态、取消、删除和过期后释放。
4. 8076 与 Web 默认只监听 `127.0.0.1`，首版不建立用户、登录、项目、租户或业务接口 API-key 鉴权；该口径覆盖 REQ-011 的统一业务鉴权，但不允许默认开放到局域网或公网。
5. 自动转写活动任务因进程重启丢失内存凭据时明确失败为 `CREDENTIAL_LOST`；已有转写任务继续沿用整任务重跑。
6. 任务公开事实增加输入模式、转写来源、供应商和转写阶段；ASR 失败不启动 M1，M1 `partial` 继续映射为任务成功并保留真实警告。
7. Web 支持临时 ASR 配置、连接验证、输入预检、任务阶段、刷新恢复任务 ID、音频同步句段、本地 speaker 稳定颜色、`unknown`/置信/风险/partial 展示、取消、删除与 JSON/TXT/SRT/VTT 下载。

### 安全与边界

- 浏览器只可在 `sessionStorage` 保存非敏感任务 ID，不保存音频、转写、结果或任何凭据；配置页刷新即丢失凭据。
- 首版现成转写只接受标准 JSON 上传或粘贴，不解析纯文本、SRT/VTT，也不实现自动时间对齐。
- 原始供应商响应默认不落盘；结果只记录脱敏来源、模型、调用时间和规范化版本。
- “可信”表示来源、失败、置信和风险可审计，不承诺文本或说话人识别绝对正确；M1 已知精度风险继续有效。
- 不新增人工改簇、跨录音身份、数据库队列、多进程、多节点或持久凭据。

### 验收

- 两种入口均可通过浏览器完成创建、状态查看、复核、四种导出和删除；自动入口分别具备腾讯、阿里真实适配能力。
- 自动测试覆盖 provider 成功和失败映射、字段互斥、凭据不落盘、取消、重启丢凭据、partial、过期、浏览器存储和播放器同步。
- 使用用户提供的腾讯、阿里测试凭据各完成一次真实闭环；未提供凭据时必须如实记录为未验证，不以 mock 代替真实联调。
