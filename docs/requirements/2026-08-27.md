# 2026-08-27 需求记录

## REQ-001 独立声音分离服务工作区初始化

### 用户原话

> 你去父目录的voiceanalysis下面，建立文档、配置和环境，把所有新建声音分离服务所需要的配置、环境、地址、密钥等都写进去，并建立本地git；最后把本项目的agents.md复制过去；

### 规范化需求

1. 在 `smart_badge-main/voiceanalysis` 建立独立工作区和本地 Git 仓库。
2. 建立可追溯的需求、架构、接口、配置、密钥和本地运行文档。
3. 以 Smart Badge 已退役但有代码证据的声音分离路线为技术基线：pyannote 窗口细化与 ECAPA 向量推理使用隔离进程和隔离 Python 环境。
4. 固定本地端点为 `8077 /embed`、`8077 /health`、`8078 /segment`、`8078 /health`；容器内端点使用独立 DNS 名，不复用 Smart Badge 进程。
5. 实际本地服务访问密钥写入被 Git 忽略的 `.env`；模板和文档不保存明文。当前没有可复用的 Hugging Face 访问令牌，模型默认按离线目录加载，令牌只作为首次合法下载的可选配置。
6. 不复制 Smart Badge 的 LLM、腾讯 ASR、数据库、Redis、SAP、企业微信或对象存储密钥；声音分离核心服务以调用方提供的音频和时间窗口为输入。
7. 建立两个可复现环境：`voice-embedding` 使用 SpeechBrain ECAPA，`window-refine` 使用 pyannote.audio；模型与运行数据不进入普通 Git 对象。
8. 将 Smart Badge 当前根目录 `AGENTS.md` 原样复制到新仓库根目录。

### 非目标

- 本次不实现声音分离业务代码，不接入 Smart Badge 当前主链，不恢复已退役的声纹身份系统。
- 不部署生产、不修改 Smart Badge 配置或数据、不复制真实录音和员工声纹材料。
- 不把句内说话人簇解释为跨录音身份。

- `.env` 和运行/模型产物被 Git 忽略，仓库中只提交无密模板。
